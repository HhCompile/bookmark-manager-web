# 技术方案建议书

## 方案对比

### 方案 A：渐进式重构（推荐）

#### 实施步骤
1. **添加 SQLite 数据库**（2小时）
   - 使用 SQLAlchemy ORM
   - 迁移现有 JSON 数据
   - 保持数据完整性

2. **实现用户认证**（3小时）
   - JWT Token 机制
   - bcrypt 密码加密
   - Token 刷新机制

3. **调整 API 路径**（1小时）
   - `/v1/xxx` → `/api/xxx`
   - 保留旧路径兼容性（可选）

4. **统一响应格式**（1小时）
   - 包装现有响应
   - 添加 timestamp 字段

5. **添加文件夹功能**（2小时）
   - 数据库表设计
   - CRUD 接口实现

**总工作量**: 约 9 小时
**优点**: 完全满足前端规范，可扩展性强
**缺点**: 工作量较大

### 方案 B：前端适配后端

#### 后端保持不变
- 继续使用 `/v1/xxx` API 路径
- 继续使用现有响应格式
- 简单 API Key 认证

#### 前端需要调整
1. 修改 API 客户端 baseURL
2. 调整响应数据处理
3. 适配现有字段命名

**总工作量**: 约 2 小时（前端）
**优点**: 快速集成，工作量小
**缺点**: 前端需要妥协，不够规范

---

### 方案 C：混合方案

#### 后端调整
1. 添加 SQLite + 用户管理（3小时）
2. 响应格式调整为标准格式（1小时）
3. 保持 `/v1/xxx` 路径（不修改）

#### 前端调整
1. 适配 `/v1/xxx` 路径（10分钟）
2. 使用新响应格式（30分钟）

**总工作量**: 约 4.5 小时
**优点**: 平衡双方工作量
**缺点**: 路径不统一
